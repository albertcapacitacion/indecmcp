# Project experiences

## 2026-11-03 — repeatable end-to-end checks

- A shared nine-call E2E suite now verifies all six tools through real local MCP HTTP and through fresh native hosted calls. Its assertions independently recalculate real wage growth, check reference periods, preserve cache retrieval times and reject substituted missing periods. Both paths passed against real INDEC data.
- A hosted recording validator is explicitly an audit step, not an authenticated caller. The actual hosted calls use Sites' installed plugin connection; replaying yesterday's JSON cannot establish a new network run. No service token, forged identity or exported client credentials were introduced to automate around this boundary.
- Negative tests also corrupt otherwise valid unit fixtures to ensure calculation, alignment, missing-case and metadata mistakes cannot quietly produce a green validator result. Fresh run artifacts are written under ignored outputs/e2e/ with unique filenames.

## 2026-11-03 — wage endpoint recovery and contract drift

- A standalone console curl check found the documented wage endpoint reachable, despite earlier authenticated 404s. Minimal and exact application queries both succeeded. The earlier response was evidence of an observation at that time, not a permanent endpoint state; rechecking the simplest request prevented treating it as a lasting blocker.
- The rendered official documentation now types wage values as number|null while the retained supplied OpenAPI file says string|null. Live numeric rows confirmed the new contract. The original specification and earlier integration samples remain untouched; the current override and its evidence are explicit in WAGES.md.
- The two wage tools reuse the existing bounded series client and shared cache. Comparisons align the exact reference month/window and use published official rates, with real growth distinct from a percentage-point gap. Twenty-four real local HTTP MCP calls verified all six tools and all 16 wage mappings; synthetic tests also cover publication lags, nulls and unavailable exact months.
- The same implementation passed seven native hosted calls, covering both wage tools, annual/monthly/accumulated windows, the unregistered sector, a persistent D1 cache hit and an unavailable exact month. No new plugin, secret rotation or authentication workaround was needed.

## 2026-11-02 — first live vertical slice

- The supplied OpenAPI file is essential for endpoint mapping, but authenticated responses add `valor_null` and other `*_null` statistical-sign fields that it does not declare. Strict validation of known identifying fields plus preservation of additional observation fields avoids silently losing provisional/unavailable signs.
- The documented `/indice_salarios` endpoint returns HTTP 404 even with a minimal authenticated query. The tools expose that failure explicitly. A fixture or an alternative source would not establish a successful INDEC wage integration.
- The first actual SDK HTTP tool call returned the latest available national monthly IPC observation for 2026-09. That did not establish an October observation or a release date; the output distinguishes reference month, retrieval time and unknown publication date.
- Sites prefers the 2026-07-28 stateless discovery protocol. The installed v1 SDK initially supported only older revisions; official SDK v2 provides modern discovery and legacy Streamable HTTP from one definition set, avoiding a custom protocol shim.
- Shared rate counters use one conditional SQLite/D1 upsert per bucket. Integration tests with multiple state instances confirm the limit cannot be exceeded through separate in-process state objects. Memory-only counters remain restricted to local development.
- Stable bounded pagination carries the complete documented ordering key. Duplicate periods, inconsistent ordering and changing total counts fail closed. An operational cache is not an immutable publication archive.
- The approved public name is INDEC MCP, with English base listing text and Spanish metadata. The existing GitHub name indecmcp was explicitly retained; the package remains indec-mcp. Apache-2.0 and an original chart/wordmark direction were approved.
- Native Sites MCP forwarding omits the HTTP Host header while retaining the Site origin in the Request URL. The first hosted discovery received 403 from the SDK's missing-Host guard. Explicit URL-hostname validation plus validation of a supplied Host header handles this transport shape without accepting arbitrary hosts. Regression tests cover the missing, matching and hostile-host cases.
- An installed native plugin and successful server discovery/tool listing did not prove that ChatGPT attached its tools to a new selected-plugin chat. The first reported answer came from browsing, with no data invocation in Worker logs. Matching statistics were not sufficient evidence. Once the tools attached, actual native invocations established authentication separately from upstream retrieval.
- After the native tools attached, the first hosted data request failed before reaching INDEC. Redacted diagnostics identified that the Sites/Workers runtime rejects `redirect: "error"`, although Node supports it. The portable fix uses `redirect: "manual"` and explicitly rejects all 3xx responses, preserving credential containment. Regression tests verify that a redirect is never followed.
- The corrected Site passed actual native calls for latest IPC, official accumulated IPC, GBA baskets, EPH unemployment and adjusted activity. The second latest-IPC call hit D1 cache without changing retrieved_at. An October-only query returned unavailable, while both wage tools preserved the upstream 404. These separate checks made the final integration result reviewable without relying on browsed answers or fixture values.
